# 多賣家電商平台 使用者故事與驗收條件

> 狀態：定版
> 版本：1.5
> 最後更新：2026-10-14
> 範圍：訂單、付款與退款、賣家、折價券、限時搶購、查詢、規則告知、認證與權限的核心情境

完整的業務規則以《需求_001_需求規格》為準，本文件以具體情境說明這些規則的驗收方式。

## 閱讀方式

每條故事的驗收條件由三部分組成：

- **前提**：情境開始前系統所處的狀態
- **當**：發生的操作或事件
- **則**：預期的結果

只有一條主線的故事以清單列出結果；有多個分支的故事以表格列出，每一列是一個獨立的情境，彼此互斥，也各自對應一個測試案例。涉及金額的故事以步驟表列出每一步的帳本變化。

## 1. 名詞

| 名詞 | 說明 |
|---|---|
| 結帳單 | 會員一次結帳產生的單據，最多對應一筆成功的付款 |
| 子訂單 | 結帳單依賣家拆出的訂單，每張對應一個賣家 |
| 預扣 | 暫時保留庫存，尚未真正扣除 |
| 冪等鍵 | 用戶端為每次操作產生的唯一識別，用來辨識重複請求 |
| 實付金額 | 子訂單原始金額扣除其分攤的折價券折扣 |

## 2. 主要業務規則

以下規則已確認，是各項驗收條件的前提。

| 編號 | 規則 | 採用的理由 |
|---|---|---|
| R1 | 按下結帳時預扣庫存，付款成功後才確認扣除；加入購物車不會保留庫存 | 避免會員付了錢卻沒貨；代價是未付款的結帳單會暫時佔住庫存 |
| R2 | 結帳單 30 分鐘內未付款成功即取消並釋放庫存，搶購為 10 分鐘 | 限制庫存被佔住的時間 |
| R3 | 結帳時任一商品庫存不足，整筆結帳失敗 | 規則單純，會員不會收到與預期不同的訂單 |
| R4 | 付款失敗不取消結帳單，時限內可重新付款 | 換一種付款方式重試是常見情況 |

## 3. 訂單

### O1 結帳並拆單

身為會員，我想一次結帳購物車內來自不同賣家的商品，這樣我只需要付款一次。

前提：購物車內有賣家甲的商品 2 件與賣家乙的商品 1 件，庫存充足。

當：會員選擇一筆收件資訊並送出結帳。

則：

- 建立 1 張結帳單與 2 張子訂單，各子訂單只包含該賣家的商品
- 結帳單金額等於各子訂單金額的總和
- 結帳單與子訂單的狀態皆為「待付款」
- 各商品的可賣數量減少、預扣數量增加，並各留下一筆異動紀錄
- 子訂單保存當下的商品名稱、單價與數量，之後賣家改價不影響既有子訂單
- 兩張子訂單都保存同一筆收件資訊的快照，之後會員修改收件資訊不影響既有子訂單
- 購物車移除已結帳的商品

### O2 結帳失敗

身為會員，我想在商品買不到時立刻知道是哪一項，這樣我可以調整購物車。

當：會員送出結帳。

| 情境 | 前提 | 則 |
|---|---|---|
| 庫存不足 | 購物車內有一項商品的可賣數量少於購買數量 | 結帳失敗，回應指出該商品與可購買數量 |
| 商品已下架 | 購物車內有一項商品已被賣家下架 | 結帳失敗，回應指出該商品已下架 |
| 數量超過上限 | 購物車內有一項商品的數量為 100 件 | 結帳失敗，回應指出單一商品每次最多 99 件 |
| 已有待付款 | 會員已有一張一般的「待付款」結帳單 | 結帳失敗，回應提示先完成付款或取消既有的結帳單 |
| 同時送出 | 沒有待付款結帳單的會員同時送出兩筆不同的結帳 | 只有一筆成功，另一筆依「已有待付款」處理 |

以上各情境都不建立任何單據、不預扣任何庫存，購物車內容維持不變。

### O3 重複送出結帳

身為會員，我想在網路不穩而重複送出時不會產生兩筆訂單。

| 情境 | 前提 | 當 | 則 |
|---|---|---|---|
| 先後重送 | 會員已用某個冪等鍵成功結帳 | 以相同的冪等鍵再次送出 | 回傳第一次建立的結帳單，不建立新單據，庫存不再預扣 |
| 同時送出 | 無 | 兩個相同冪等鍵的請求同時到達 | 只有一個請求建立結帳單，另一個回傳同一張結帳單 |

### O4 逾時未付款自動取消

身為平台，我想自動取消逾時未付款的結帳單，這樣庫存不會被長期佔住。

前提：結帳單建立已超過 30 分鐘，狀態為「待付款」。

| 情境 | 當 | 則 |
|---|---|---|
| 沒有處理中的付款 | 逾時取消任務執行 | 結帳單與其所有子訂單變為「已取消」，預扣的庫存全部釋放 |
| 有處理中的付款 | 逾時取消任務執行 | 不取消 |
| 處理中的付款後來確定失敗 | 下一次逾時取消任務執行 | 取消，結果同第一列 |
| 付款已成功但訂單尚未更新 | 付款剛成功、結帳單仍顯示「待付款」時，逾時取消任務執行 | 不取消；結帳單隨後變為「已付款」 |
| 任務尚未處理到這張結帳單 | 會員發起付款 | 付款被拒絕 |

### O5 子訂單自動簽收與自動完成

身為賣家，我想在買家沒有確認收貨時也能如期收到款項。

當：子訂單狀態推進任務執行。

| 情境 | 前提 | 則 |
|---|---|---|
| 自動簽收 | 子訂單「已出貨」滿 7 天，會員未確認收貨 | 子訂單變為「已簽收」 |
| 自動完成 | 子訂單「已簽收」滿 7 天，沒有進行中的退款申請 | 子訂單變為「已完成」，並依賣家類型記入帳本 |
| 退款申請中 | 子訂單簽收已滿 7 天，但為「退款申請中」 | 不標記為完成 |
| 重複執行 | 任務對相同的資料再執行一次 | 狀態與帳本分錄都不會重複產生 |

### O6 會員主動取消

身為會員，我想在付款前取消結帳單。

當：會員取消結帳單。

| 情境 | 前提 | 則 |
|---|---|---|
| 可以取消 | 一般結帳單為「待付款」，沒有處理中的付款 | 結帳單與其所有子訂單變為「已取消」，預扣的庫存全部釋放；結帳單的商品放回購物車 |
| 付款處理中 | 結帳單有一筆處理中的付款 | 取消被拒絕 |
| 已付款 | 結帳單為「已付款」 | 取消被拒絕，會員需改走退款流程 |

## 4. 付款與退款

### P1 付款成功

身為會員，我想在付款成功後看到訂單已成立。

前提：結帳單為「待付款」。

當：金流回報付款成功。

則：

- 結帳單與其所有子訂單變為「已付款」
- 各商品的預扣數量減少，並各留下一筆「確認」的異動紀錄
- 帳本的金流存款與代管款項各增加會員實付金額
- 各賣家收到新訂單的通知事件

### P2 金流重複回報

身為平台，我想在金流重複回報同一筆結果時只處理一次。

前提：某筆付款已被處理為成功。

當：金流再次回報同一筆付款成功。

則：

- 系統回應處理成功，但不產生任何狀態變更
- 帳本沒有新增分錄
- 賣家不會收到重複的通知事件

### P3 付款結果不明

身為會員，我不想因為系統之間連線逾時就被誤判為付款失敗。

前提：系統向金流送出付款請求後連線逾時，沒有收到結果。

則：

- 付款狀態為「處理中」，不是「失敗」
- 預扣的庫存不被釋放
- 會員不能對同一張結帳單發起新的付款
- 付款結果查詢任務之後主動向金流查詢這筆付款

查詢得到結果時：

| 情境 | 則 |
|---|---|
| 金流回覆成功 | 依 P1 處理 |
| 金流回覆失敗 | 付款變為「失敗」，結帳單維持「待付款」，會員可重新付款 |

### P4 付款成功但結帳單已取消

身為會員，如果我的付款在結帳單取消後才成功，我想自動拿回款項。

前提：結帳單已被取消，庫存已釋放。

當：金流回報該結帳單付款成功。

則：

- 結帳單維持「已取消」，不恢復訂單
- 系統自動發起全額退款
- 帳本記錄收款與退款兩組分錄

### P5 付款失敗後重新付款

身為會員，我想在付款失敗後換一種方式再付一次。

前提：結帳單為「待付款」且尚未逾時，前一筆付款為「失敗」。

當：會員再次發起付款，且這次成功。

則：

- 系統建立一筆新的付款紀錄
- 預扣的庫存與鎖定的折價券在重新付款期間維持不變
- 付款成功後依 P1 處理
- 該結帳單只有一筆狀態為「成功」的付款

### P6 尚未出貨的子訂單退款

身為會員，我想在賣家出貨前退掉其中一個賣家的商品，其他訂單不受影響。

前提：已付款的結帳單包含子訂單甲（600 元）與子訂單乙（400 元），皆尚未出貨，未使用折價券。

| 情境 | 當 | 則 |
|---|---|---|
| 申請 | 會員申請子訂單甲退款 | 自動核准，系統向金流發起 600 元的退款 |
| 退款成功 | 金流回報退款成功 | 子訂單甲變為「已退款」，子訂單乙維持「已付款」；甲的商品自動回補到一般庫存並留下「退款回補」的異動紀錄；帳本的金流存款與代管款項各減少 600 元 |
| 重複送出 | 相同的退款請求再次送出 | 只退款一次 |
| 超額退款 | 退款會使同一筆付款的累計退款超過原付款金額 | 退款被拒絕 |

### P7 已出貨的子訂單退款

身為賣家，我想自己決定是否接受已出貨商品的退款，並在收到退貨後才回補庫存。

前提：子訂單已簽收，簽收未滿 7 天，會員已申請退款，子訂單為「退款申請中」且不會被自動完成。

| 情境 | 當 | 則 |
|---|---|---|
| 賣家核准 | 賣家核准申請 | 系統向金流退款，成功後子訂單變為「已退款」；庫存不自動回補 |
| 收到退貨 | 賣家確認收到退貨並選擇回補 | 商品回補到一般庫存 |
| 賣家拒絕 | 賣家拒絕申請 | 子訂單回到「已簽收」，7 天仍從簽收時起算；會員不可再次申請 |
| 申訴期限內 | 賣家拒絕後尚未滿 3 天，會員未申訴，且簽收已滿 7 天 | 子訂單不會被自動完成 |
| 未申訴 | 賣家拒絕後滿 3 天，會員未申訴 | 申訴期限結束，子訂單可依規則自動完成 |
| 提出申訴 | 賣家拒絕後 3 天內，會員提出申訴 | 子訂單再次變為「退款申請中」 |
| 申訴核准 | 會員申訴，平台營運裁決應退款 | 依核准處理，並留下裁決的稽核紀錄 |
| 申訴駁回 | 會員申訴，平台營運維持拒絕 | 子訂單回到「已簽收」；爭議結束，會員不可再申訴，子訂單可依規則自動完成 |
| 賣家未處理 | 賣家 3 天內未核准也未拒絕 | 系統自動核准 |
| 已完成 | 會員對「已完成」的子訂單申請退款 | 申請被拒絕 |

## 5. 賣家

### S1 賣家不能存取其他賣家的資料

身為賣家，我不希望其他賣家看到或修改我的商品、訂單與結算資料。

前提：賣家甲的帳號已登入。

| 情境 | 當 | 則 |
|---|---|---|
| 查詢他人訂單 | 以賣家乙的子訂單編號查詢 | 回應查無資料，不透露該訂單是否存在 |
| 修改他人資料 | 嘗試修改賣家乙的商品或庫存 | 操作被拒絕，資料沒有任何變更 |
| 查詢報表 | 查詢銷售報表或結算對帳單 | 結果只包含賣家甲的資料 |

### S2 平台自營與外部賣家的結算差異

身為平台，我想讓自營商品與外部賣家商品走相同的銷售流程，但金流分開處理。

前提：結帳單包含平台自營賣家的子訂單（500 元）與外部賣家的子訂單（1,000 元），未使用折價券，該外部賣家的抽成比例為 10%。

| 步驟 | 事件 | 帳本變化與結果 |
|---|---|---|
| 1 | 付款成功 | 金流存款與代管款項各增加 1,500 元；平台營收與應付賣家款項不變 |
| 2 | 平台自營的子訂單完成 | 代管款項減少 500 元，平台營收增加 500 元 |
| 3 | 外部賣家的子訂單完成 | 代管款項減少 1,000 元，應付賣家款項增加 1,000 元 |
| 4 | 賣家結算任務執行 | 應付賣家款項減少 100 元，抽成收入增加 100 元，產生一張 900 元的撥款單；平台自營賣家不產生撥款單 |
| 5 | 撥款成功 | 應付賣家款項與金流存款各減少 900 元 |

另外：平台營運之後將該賣家的抽成比例調為 15%，既有子訂單仍以 10% 計算。

### S3 賣家報名搶購活動

身為賣家，我想拿自己的商品報名平台的搶購檔期，這樣可以增加曝光與銷量。

前提：平台已開設一個尚未開始的搶購檔期，賣家某商品的一般可賣數量為 100 件。

| 情境 | 當 | 則 |
|---|---|---|
| 正常報名 | 以活動價、釋出 30 件、每人限購 2 件報名 | 報名為「待審核」，庫存不變 |
| 審核通過 | 平台營運核准上述報名 | 搶購可賣數量 30 件、一般可賣數量 70 件，留下「搶購劃撥」的異動紀錄 |
| 數量或價格不符 | 釋出數量超過一般可賣數量，或活動價不低於原價 | 報名被拒絕 |
| 檔期重疊 | 該商品在同一段時間已參加另一個檔期 | 報名被拒絕 |
| 審核時庫存不足 | 審核時一般可賣數量已少於釋出數量 | 審核失敗，庫存不變 |
| 逾期未審 | 檔期開始時報名仍為「待審核」 | 報名自動被拒絕，庫存不變 |
| 檔期結束 | 檔期結束時搶購可賣數量剩 5 件 | 5 件歸還一般庫存，留下「搶購歸還」的異動紀錄 |

## 6. 折價券

### C1 結帳使用折價券

身為會員，我想在結帳時使用折價券，而且訂單沒成立時能把券拿回來。

前提：會員有一張「可使用」的折價券，折抵 100 元，最低消費 500 元。

結帳時：

| 情境 | 當 | 則 |
|---|---|---|
| 正常使用 | 以該券結帳一張 1,000 元的結帳單 | 券變為「已鎖定」，應付金額為 900 元 |
| 查詢可用折價券 | 結帳金額 400 元時查詢可用的折價券 | 該券不在可用清單中 |
| 未達門檻仍帶入 | 請求繞過介面，以該券結帳一張 400 元的結帳單 | 結帳失敗 |
| 同時使用 | 同一張券同時被兩筆結帳選用 | 只有一筆成功鎖定 |
| 結帳失敗 | 結帳因庫存不足而失敗 | 券維持「可使用」 |

券鎖定之後：

| 情境 | 當 | 則 |
|---|---|---|
| 付款失敗 | 付款失敗 | 券維持「已鎖定」 |
| 付款成功 | 付款成功 | 券變為「已核銷」 |
| 鎖定後過期再付款 | 券在付款前過期，之後付款成功 | 付款仍可完成，券變為「已核銷」 |
| 結帳單取消 | 結帳單逾時取消或被會員主動取消 | 券回到「可使用」 |
| 過期後取消 | 券在鎖定期間過期，之後結帳單被取消 | 券變為「已失效」 |

### C2 折扣分攤與退款

身為平台，我想把折扣正確分攤到各子訂單，這樣退款與結算的金額才不會出錯。

前提：結帳單包含外部賣家甲的子訂單（700 元）與外部賣家乙的子訂單（300 元），使用一張折抵 100 元的券，兩個賣家的抽成比例皆為 10%。

| 步驟 | 事件 | 帳本變化與結果 |
|---|---|---|
| 1 | 結帳 | 子訂單甲分攤 70 元折扣，子訂單乙分攤 30 元折扣 |
| 2 | 付款成功 | 會員實付 900 元，金流存款與代管款項各增加 900 元 |
| 3 | 子訂單甲退款成功 | 退給會員 630 元，券不歸還；金流存款與代管款項各減少 630 元 |
| 4 | 子訂單乙完成 | 代管款項減少 270 元，折價券費用增加 30 元，應付賣家款項增加 300 元 |
| 5 | 賣家結算任務執行 | 以原始金額 300 元計算，平台抽成 30 元，賣家乙的撥款單為 270 元 |

尾數處理：三張金額皆為 100 元的子訂單使用折抵 100 元的券，分攤金額為 34 元、33 元、33 元，多出的 1 元歸給編號最小的子訂單。

## 7. 限時搶購

### F1 搶購商品

身為會員，我想在搶購檔期內以活動價買到限量商品。

前提：搶購檔期已開始，某商品的搶購可賣數量為 500 件，每人限購 2 件。

| 情境 | 當 | 則 |
|---|---|---|
| 正常搶購 | 會員以立即購買下單 2 件 | 建立只含該商品的結帳單，價格為活動價，搶購可賣數量減少 2 件 |
| 已有一般待付款 | 會員已有一張一般的待付款結帳單，以立即購買下單 | 可以下單，不受一般結帳單影響 |
| 已有搶購待付款 | 會員已有一張搶購的待付款結帳單，再以立即購買下單另一項搶購商品 | 下單失敗，提示先完成付款或取消 |
| 超過限購 | 同一會員再下單 1 件 | 下單失敗，原因為超過每人限購數量 |
| 逾時未付款 | 會員的搶購結帳單 10 分鐘內未付款 | 結帳單取消，2 件歸還搶購可賣數量，限購額度恢復 |
| 檔期結束後才取消 | 結帳單在檔期結束之後才被取消 | 2 件直接歸還一般庫存 |
| 查詢可用折價券 | 會員在立即購買時查詢可用的折價券 | 回應沒有可用的券，介面不提供選券 |
| 強行帶入折價券 | 請求繞過介面，仍帶有折價券 | 請求被拒絕，券維持「可使用」 |
| 不在檔期內 | 檔期尚未開始或已經結束 | 無法以活動價下單 |
| 已售完 | 搶購可賣數量為 0 | 下單失敗，原因為已售完 |
| 透過購物車購買 | 檔期內透過購物車購買同一商品 | 以原價從一般庫存購買，不計入限購數量 |

### F2 搶購不超賣

身為賣家，我不希望搶購賣出的數量超過我釋出的數量。

前提：某商品的搶購可賣數量為 500 件，每人限購 1 件。

當：1 萬名會員同時下單各 1 件。

則：

- 恰好 500 筆下單成功，其餘失敗並得知已售完
- 搶購可賣數量為 0，預扣數量為 500，兩者皆不為負
- 異動紀錄的加總與庫存數字一致
- 同一時間一般商品的瀏覽與下單回應時間不受影響

## 8. 查詢

### Q1 搜尋商品

身為訪客，我想用關鍵字找到商品並依條件篩選，這樣我能快速找到想買的東西。

前提：平台上有多個賣家的上架商品。

| 情境 | 當 | 則 |
|---|---|---|
| 篩選與排序 | 以關鍵字搜尋，指定價格區間並依價格由低到高排序 | 只列出名稱或描述符合、價格在區間內的上架商品，依價格由低到高排列，每頁預設 20 筆 |
| 已下架商品 | 同上 | 已下架的商品不會出現 |
| 翻頁過深 | 要求第 1,000 筆之後的結果 | 請求被拒絕 |
| 新上架 | 賣家上架一項新商品 | 60 秒內可以被搜尋到 |
| 下架 | 賣家下架一項商品 | 60 秒內不再出現在搜尋結果中 |

### Q2 商品頁的價格與庫存狀態

身為訪客，我想在商品頁看到正確的價格，並知道還買不買得到。

| 情境 | 前提或當 | 則 |
|---|---|---|
| 有貨 | 可賣數量為 50 件 | 顯示「有貨」，不顯示確切數量 |
| 即將售完 | 可賣數量降到 10 件以下 | 5 秒內改為顯示「即將售完」 |
| 已售完 | 可賣數量降到 0 | 5 秒內改為顯示「已售完」 |
| 改價 | 賣家調整商品價格 | 5 秒內顯示新價格 |
| 頁面價格過時 | 商品頁仍顯示舊價格時會員送出結帳 | 結帳以新價格計算 |
| 搶購中 | 該商品正在搶購檔期中 | 同時顯示原價、活動價與搶購狀態 |

### Q3 查看我的訂單

身為會員，我想在下單後馬上看到訂單，並追蹤每個賣家的處理進度。

前提：會員剛完成一筆包含兩個賣家商品的結帳。

| 情境 | 當 | 則 |
|---|---|---|
| 剛下單 | 立刻查詢我的訂單列表 | 第一筆就是這張結帳單，並顯示兩張子訂單各自的狀態 |
| 依狀態篩選 | 依「已出貨」篩選 | 只列出含有已出貨子訂單的結帳單 |
| 訂單詳情 | 查看訂單詳情 | 可看到各子訂單的商品快照、折扣分攤、付款紀錄、退款紀錄與狀態變更歷程 |
| 他人訂單 | 以其他會員的結帳單編號查詢 | 回應查無資料 |

### Q4 賣家查詢子訂單

身為賣家，我想找出待出貨的訂單，這樣我能安排出貨。

前提：賣家甲有多張不同狀態的子訂單，其中有些和其他賣家的子訂單屬於同一張結帳單。

| 情境 | 當 | 則 |
|---|---|---|
| 篩選待出貨 | 依「已付款」與日期區間篩選 | 只列出賣家甲在該區間內待出貨的子訂單，由新到舊排列 |
| 同一結帳單的其他賣家 | 同上 | 不包含屬於其他賣家的子訂單；金額只顯示賣家甲子訂單的原始金額 |
| 剛付款的訂單 | 會員剛付款成功 | 賣家甲在 5 秒內可以在列表中查到這張子訂單 |
| 預設分頁 | 未指定每頁筆數 | 每頁 20 筆，回應包含總筆數與總頁數 |
| 調整筆數與跳頁 | 選擇每頁 100 筆並跳到第 3 頁 | 回應第 201 到 300 筆 |
| 不支援的筆數 | 指定每頁 30 筆 | 請求被拒絕 |
| 未指定日期區間 | 查詢時沒有指定日期區間 | 預設查詢最近 30 天 |
| 日期區間過長 | 指定超過 1 年的日期區間 | 請求被拒絕 |
| 結果過多 | 符合條件超過 10,000 筆 | 總筆數回應「超過 10,000 筆」，第 10,000 筆之後無法查詢 |

### Q5 查詢付款結果

身為會員，我想在付款後立刻知道有沒有成功。

前提：會員已對某張結帳單發起付款。

| 情境 | 當 | 則 |
|---|---|---|
| 一般查詢 | 查詢付款結果 | 回應目前的狀態：「處理中」、「成功」或「失敗」 |
| 狀態剛改變 | 付款剛由「處理中」變為「成功」 | 下一次查詢立刻回應「成功」 |
| 尖峰查詢 | 搶購期間 1 萬名會員同時反覆查詢各自的付款結果 | p99 低於 200 毫秒，下單的回應時間不受影響 |
| 他人結帳單 | 查詢其他會員結帳單的付款結果 | 回應查無資料 |

身為平台，我想在會員同意條款後留下證明，並在條款更新時重新取得同意。

|---|---|---|

| 搶購結帳 | 會員在 20:00 完成搶購結帳 | 回應的付款期限為 20:10 |

## 10. 認證與權限

### A1 登入失敗鎖定

身為平台，我想阻擋以猜測密碼的方式登入他人帳號。

前提：某會員帳號目前沒有被鎖定。

| 情境 | 當 | 則 |
|---|---|---|
| 連續失敗 | 以錯誤密碼連續登入 5 次 | 帳號鎖定 15 分鐘，並留下稽核紀錄 |
| 鎖定期間 | 鎖定期間以正確密碼登入 | 登入失敗，回應提示帳號暫時鎖定 |
| 鎖定結束 | 15 分鐘後以正確密碼登入 | 登入成功 |
| 失敗後成功 | 連續失敗 4 次後以正確密碼登入 | 登入成功，失敗次數歸零 |

### A2 營運角色的權限

身為平台，我想讓每位營運人員只能做自己職責內的事。

| 情境 | 當 | 則 |
|---|---|---|
| 職責內的操作 | 具有財務營運角色的帳號處理一筆對帳差異 | 操作成功 |
| 職責外的操作 | 只有財務營運角色的帳號修改賣家抽成比例 | 操作被拒絕 |
| 權責分離 | 只有營運管理者角色的帳號處理撥款失敗 | 操作被拒絕 |
| 多個角色 | 同時具有活動營運與客服營運角色的帳號 | 可以審核搶購報名，也可以裁決退款申訴 |
| 共同權限 | 任一營運角色的帳號查詢訂單 | 查詢成功 |
| 角色被移除 | 營運管理者移除某帳號的財務營運角色 | 該帳號最晚 15 分鐘後無法再處理對帳差異 |

### A3 賣家角色的權限

身為賣家管理者，我想讓一般成員處理日常作業，但不能看到財務資料。

| 情境 | 當 | 則 |
|---|---|---|
| 日常作業 | 一般成員標記出貨、審核退款 | 操作成功 |
| 財務資料 | 一般成員查看結算對帳單 | 操作被拒絕 |
| 報名搶購 | 一般成員報名搶購 | 操作被拒絕 |
| 管理帳號 | 管理者新增一個一般成員帳號 | 新帳號建立，只能存取所屬賣家的資料 |
